You are helping resolve a paused git operation (rebase/merge/cherry-pick) using `git-hex` MCP tools.

What happened (optional): ${subject}
Context (optional): ${details}

Workflow (repeat until clean):
1) Call `git-hex-getConflictStatus` with:
   - `repoPath` (when needed): ${repoPath}
   - `includeContent`: ${includeContent}
   - `maxContentSize`: ${maxContentSize}
2) If `inConflict=false`, stop and explain the next safe action:
   - If an operation is still in progress, call `git-hex-continueOperation`.
3) If `inConflict=true`, handle one file at a time:
   - For delete conflicts: decide `keep` vs `delete`, then call `git-hex-resolveConflict`.
   - For content conflicts: instruct the user to edit the file manually, then call `git-hex-resolveConflict` to mark it resolved.
4) After resolving at least one file, call `git-hex-continueOperation`.
   - If it returns paused again, loop back to step 1.
5) If the user wants to abandon the operation, call `git-hex-abortOperation`.

Output format:
- State what operation is paused (if known) and how many files conflict.
- Then give exactly one next tool call (name + JSON args).

## LLM Decision Guide

**Understanding conflict status response**:
| Field | Meaning |
|-------|---------|
| `inConflict: true` | Operation paused, conflicts need resolution |
| `inConflict: false` + operation in progress | All conflicts resolved, ready to continue |
| `conflictType` | `rebase`, `merge`, `cherry-pick`, or `revert` |
| `currentStep/totalSteps` | Progress through multi-commit operation |
| `conflictingFiles[].conflictType` | Per-file conflict type (see below) |

**Per-file conflict types**:
- `both_modified`: Content conflict - user must edit file
- `deleted_by_us`: We deleted, they modified - ask keep or delete
- `deleted_by_them`: They deleted, we modified - ask keep or delete
- `added_by_both`: Both added same file - user must merge content

**Resolution workflow**:
```
getConflictStatus → (for each file) → resolveConflict → continueOperation
                                                              ↓
                                                     (if more conflicts)
                                                              ↓
                                                      getConflictStatus
```

**When to use `includeContent: true`**:
- File is small enough to display (check size first)
- User needs to see the three-way diff
- Conflict is in code (not binary)

**When to suggest abort**:
- Too many conflicts (> 10 files)
- Binary files in conflict
- User seems frustrated or confused
- Conflicts are in auto-generated files

**Never do**:
- Call `resolveConflict` on a file that still has `<<<<<<<` markers
- Call `continueOperation` when `remainingConflicts > 0`
- Choose resolution strategy without user input for content conflicts
